# Change Delivery

Before declaring a change ready:

1. Inspect the working tree and preserve unrelated user changes.
2. Keep the change small and within one agreed scope.
3. Update the applicable contract when an external behavior changes.
4. Run the relevant build, tests or controlled endpoint verification.
5. State what was changed, how it was verified, and any work deliberately left
   for later.

Repository owners decide when to commit and push. Agents should prepare clear,
reviewable changes but never assume permission to publish them.
